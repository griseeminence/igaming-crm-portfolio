# Плейбук - шесть lifecycle-кампаний и их сценарии

Это мой рабочий плейбук по iGaming CRM: шесть кампаний, которые ведут игрока от регистрации до VIP. Каждый документ совмещает бриф (зачем кампания, кому, как измеряем) и подробный сценарий: шаги, тайминги, каналы, условия, ветки и передачу игрока дальше.

|---|---|---|---|

| 2 | [Первый депозит -> второй](02-post-ftd-second-deposit.md) | новый депозитор | второй депозит (STD) за 7 дней |

## Как кампании связаны между собой

Ни один сценарий не заканчивается тупиком: игрок либо достигает цели и переходит на следующий этап, либо уходит в более дешёвый и редкий поток.

| Откуда | Событие | Куда |
|---|---|---|
| Регистрация | `signup` | Онбординг |
| Онбординг | первый депозит (`ftd_completed`) | Второй депозит |
| Онбординг | 7 дней без депозита | *Sleepers* (редкая контентная рассылка) |
| Любая кампания | `deposit_failed` и нет успешного депозита за 30 мин | Неудачный депозит, исходная кампания продолжается |
| Второй депозит | второй депозит | *Priority* (активные игроки, обычная коммуникация) |
| Второй депозит | 7 дней без депозита | *Cooling*; в "Реактивацию", когда с последнего депозита пройдёт 14 дней |
| Активный игрок (не VIP) | 14 дней без депозита (точка уточняется по кривой естественного возврата) | Реактивация |
| Реактивация | депозит | *Priority* |
| Реактивация | 45 дней в сценарии без депозита | *Low frequency* (раз в месяц-квартал) |
| Любой | достиг порога VIP | VIP-цикл |
| Активный игрок только на спорте | условия кросс-селла | Кросс-селл |

**Состояния, на которые ссылаются сценарии:**
- *Priority* - активные депозиторы, получают обычную продуктовую коммуникацию;
- *Cooling* - игроки, которые начали остывать, вход в реактивацию;
- *Sleepers* - зарегистрировались, но так и не внесли депозит; редкий контент без бонусов;
- *Low frequency* - давно ушедшие депозиторы; одна рассылка в месяц или квартал

## Общие правила для всех кампаний

### 1. Допуск к коммуникации, всегда в этом порядке
1. **Можно ли писать?** Нет самоисключения и активного тайм-аута. Есть согласие на этот продукт (казино или спорт) и этот канал. Продукт доступен в юрисдикции игрока.
2. **Нужно ли?** RG-риск не High. При Medium никаких офферов с привязкой к депозиту и никакой срочности. Флаг бонус-абьюза означает только контент. Открытая проверка по фроду или AML означает ноль промо.
3. **Правила сценария.** Выход по целевому событию. Одновременно только один промо-сценарий. Общий лимит частоты на все кампании.

Проверки RG и самоисключения стоят **на каждом промо-сообщении**.

### 2. Приоритет, если игрок подходит под несколько кампаний
комплаенс и сервис -> неудачный депозит -> VIP -> онбординг / второй депозит -> реактивация -> кросс-селл.

Сервисные и транзакционные сообщения не попадают под лимиты частоты и не блокируются промо-сценариями.

### 3. Частота и время отправки
- не больше 1 промо-сообщения в день и 4 в неделю на игрока по всем каналам;
- SMS не чаще 1 раза в неделю, только с отдельным согласием;
- push и SMS только в дневное время по местному времени игрока (например, 09:00-21:00, или строже, если так требует рынок);
- одна идея сообщения - один канал, без дублей в тот же день;
- in-app подсказки, которые игрок видит только во время своей сессии, в лимит не входят.

### 4. Офферы
- Один продукт на один стимул: бонус казино или фрибет на спорт, не комбинированный
- Ключевые условия (отыгрыш, срок, максимальная ставка, лимит выигрыша) стоят рядом с оффером.
- Бонус не получают: RG High (а при Medium никаких офферов с привязкой к депозиту), флаг абьюза, игроки под проверкой, игроки после неудачного депозита.

### 5. Измерение
- Главный KPI, окно и размер холдаута фиксируются **до запуска**.
- Случайный холдаут на промо-шагах (обычно 5-15%; больше, если группа маленькая или базовая конверсия низкая). Сервисные и транзакционные сообщения получают все.
- Принадлежность к группе записывается в атрибут профиля (например, `winback_group = control`). Тогда сравнение тест/контроль можно посчитать в любой момент, независимо от того, где игрок в сценарии.
- Решения принимаются по инкрементальному NGR (в нём уже учтена стоимость бонусов) минус стоимость каналов.
- Результаты смотрю на 7-й и 30-й день: так видно, создаёт ли кампания действия игроков или только ускоряет те, что и так случились бы.
- Если аудитория маленькая (VIP, неудачные депозиты), результаты копятся за квартал: за месяц данных слишком мало.

### 6. Запуск и контроль
Перед запуском каждой кампании:
1. Прогнать тестовые профили по всем веткам: верифицирован / нет, с бонусом / без, RG Low / Medium / High, самоисключён, нет согласия на SMS.
2. Проверить, что выход по цели действительно срабатывает и игрок не получает "внесите депозит" после депозита.
3. Проверить персонализацию с пустыми полями (имя, любимая игра): у каждого поля должна быть подстановка по умолчанию.
4. Отправить все сообщения на внутренний тестовый список, проверить ссылки, UTM-метки, отображение на мобильных.
5. Согласовать тексты и офферы с комплаенсом.
6. Первые 48 часов смотреть на объёмы отправки, отказы доставки и жалобы.

| Роль | Зона |

## Каналы

| Канал | Для чего лучше всего | Стоимость и риск |
|---|---|---|
| In-app / на сайте | подсказки во время сессии, привычки первой недели | бесплатно, доходит только до активных игроков |
| Push | короткие напоминания по событию | бесплатно, при перегрузе игроки отключают уведомления |
| Email | подробности, персонализация, условия оффера | дёшево, нужна чистая база, чтобы не уходить в спам |
| SMS | последний толчок для ценных игроков | платно за каждое сообщение, строгие требования к согласию |
| VIP-менеджер | отношения, сервис, возврат | дороже всего, только для VIP |

Канал повышается вместе с этапом: пока игрок активен, работают in-app и push, для подробностей email, SMS идёт последним.
